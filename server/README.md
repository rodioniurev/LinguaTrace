# LinguaTrace — сервер синхронизации

Маленькая программа для вашего сервера: один файл около 7 МБ, около 13 МБ памяти, ответы за миллисекунды. На ней собираются данные со всех устройств: переводы, ошибки, тренировки, лента, «Идеи».

Как это работает:
- каждое устройство (телефон, каждый компьютер) отправляет на сервер **свой файл обмена** и забирает файлы остальных;
- объединяет данные само приложение, по тем же правилам, что и при обмене через папку. Сервер данные не разбирает, поэтому сломать объединение не может;
- раз в день сервер сохраняет предыдущую версию файла каждого устройства и хранит такие копии 14 дней;
- у каждого ключа доступа своё отдельное хранилище, так что одним сервером могут пользоваться несколько человек.

Приложение синхронизируется само: при запуске, при возвращении в приложение, раз в 10 минут и через несколько секунд после диктовки. Мысли, надиктованные на улице без ИИ, уходят на сервер; компьютер разбирает их по подписке Claude, и разбор возвращается на телефон.

## Где взять программу

Собрать сервер можно самому командами из раздела «Сборка из исходников» (понадобится Dart SDK 3.6 или новее), а готовые файлы, если они выложены, лежат в разделе Releases репозитория:

| Файл | Для чего |
|---|---|
| `linguatrace-sync-linux-x64` | обычный VPS (Intel/AMD), Linux с glibc: Debian, Ubuntu… (Alpine не подойдёт) |
| `linguatrace-sync-linux-arm64` | ARM-сервер, Raspberry Pi 4/5 (64-битная система) |
| `linguatrace-sync-windows-x64.exe` | домашний компьютер с Windows |

## Установка на Linux-сервер

Скопируйте на сервер `linguatrace-sync-linux-x64` и папку `deploy`, затем:

```bash
sudo useradd --system --home /var/lib/linguatrace --create-home linguatrace
sudo install -m 755 linguatrace-sync-linux-x64 /usr/local/bin/linguatrace-sync
sudo -u linguatrace sh -c 'linguatrace-sync new-key > /var/lib/linguatrace/keys.txt'
sudo cat /var/lib/linguatrace/keys.txt
sudo cp deploy/linguatrace-sync.service /etc/systemd/system/
sudo systemctl enable --now linguatrace-sync
curl http://127.0.0.1:8790/v1/health
```

`sudo cat …keys.txt` покажет ключ: его вы введёте в приложении. Последняя команда должна ответить `ok`.

## Доступ из интернета — только через HTTPS

На сервере ваши переводы и надиктованные мысли, поэтому снаружи к нему можно ходить только по защищённому соединению. Подойдёт любой из вариантов:

1. **Caddy, нужен домен.** Caddy сам получает и продлевает сертификат. Направьте домен на сервер, установите Caddy, впишите домен в `deploy/Caddyfile`, положите файл в `/etc/caddy/Caddyfile` и выполните `sudo systemctl reload caddy`. Адрес для приложения: `https://ваш-домен`. Сам сервер синхронизации при этом слушает только `127.0.0.1`, так уже настроено в service-файле.
2. **Tailscale, без домена и открытых портов.** Установите Tailscale на сервер, телефон и компьютеры. В service-файле замените `--host 127.0.0.1` на `--host 0.0.0.0`, а порт 8790 в интернет не открывайте. Адрес для приложения: `http://имя-сервера.ваша-сеть.ts.net:8790`. Трафик шифрует сам Tailscale.
3. **Свой сертификат.** Запустите сервер с `--cert fullchain.pem --key privkey.pem`, и он будет работать по HTTPS сам.

## Подключение приложения

На **каждом** устройстве (телефон и компьютеры) откройте **Настройки → Обмен → «Сервер синхронизации»**:
- адрес — `https://ваш-домен` или адрес Tailscale;
- ключ — строка из `keys.txt`;
- затем нажмите «Синхронизировать с сервером».

Дальше синхронизация идёт сама. Если сервер недоступен (например, на улице нет сети), приложение не мешает сообщениями. Причину последней ошибки показывает тот же раздел настроек.

## Ключи

- Новый ключ: `linguatrace-sync new-key >> /var/lib/linguatrace/keys.txt`, затем `sudo systemctl restart linguatrace-sync`.
- Один ключ — одно хранилище. Для второго человека заведите второй ключ.
- Если ключ утёк, удалите его строку из `keys.txt` и перезапустите сервер. Устройства с новым ключом сами заново отправят свои файлы.
- После 20 неверных ключей с одного адреса сервер не пускает этот адрес 10 минут.

## Резервные копии и перенос

Все данные лежат в `/var/lib/linguatrace/data`: `<хранилище>/<устройство>.json.gz`, а в `history/` — ежедневные копии. Чтобы сделать резервную копию или переехать на другой сервер, достаточно скопировать эту папку и `keys.txt`.

## Параметры

```
linguatrace-sync serve [--port 8790] [--host 0.0.0.0] [--data ./data] [--keys ./keys.txt]
                       [--cert fullchain.pem --key privkey.pem] [--max-mb 100] [--quiet]
```

Ключи можно передать и через переменную `LINGUATRACE_KEYS` (через запятую).

## Как устроен протокол

| Запрос | Что делает |
|---|---|
| `GET /v1/health` | `ok`, без ключа (для мониторинга) |
| `GET /v1/bundles` | список устройств: `device`, `etag`, `size`, `updated` |
| `GET /v1/bundles/<устройство>` | файл устройства (сжатый gzip), заголовок `ETag` |
| `PUT /v1/bundles/<устройство>` | сохранить файл (JSON, можно сжатый gzip) |
| `DELETE /v1/bundles/<устройство>` | забыть устройство (ежедневные копии остаются) |

Все запросы, кроме `health`, требуют заголовок `Authorization: Bearer <ключ>`.

## Сборка из исходников

```bash
cd server
dart pub get
dart test
dart compile exe bin/linguatrace_sync.dart --target-os linux --target-arch x64 -o build/linguatrace-sync-linux-x64
dart compile exe bin/linguatrace_sync.dart --target-os linux --target-arch arm64 -o build/linguatrace-sync-linux-arm64
dart compile exe bin/linguatrace_sync.dart -o build/linguatrace-sync-windows-x64.exe
```

Последняя команда собирает файл для той системы, на которой её запускают (в примере — Windows).
